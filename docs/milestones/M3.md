# Milestone 3 — Pressure projection

**Status:** done · **Commit:** see `git log --oneline -- docs/milestones/M3.md`

## Plan (written before coding)

* **Governing equations.** `u_new = u* − dt ∇p` with `∇·u_new = 0`, hence
  `∇²p = ∇·u*/dt`. The pressure is the Lagrange multiplier for the incompressibility
  constraint.
* **Discretisation.** `div` (faces → centres) and `grad` (centres → faces) are exact negative
  transposes on the staggered grid, so `∇²` is the symmetric 5-point Laplacian. Boundary
  conditions: **Neumann** (`∂p/∂n = 0`, mirrored ghost) at walls, obstacles, inflow and
  free-slip sides; **Dirichlet** (`p = 0`) at outflows; **periodic** wrap. Obstacles and
  (later) air cells are removed from the system with an explicit mask.
* **Stability / solvability.** The pure-Neumann case makes `A` singular: the right-hand side
  is made zero-mean and the constant mode is projected out of every iterate and of the final
  pressure. Iterative solvers use a *relative* residual `max|b − Ap| / max|b|`.
* **Correctness tests.** The operator equals a hand-written stencil and is symmetric; the
  adjoint identity `⟨div u, p⟩ = −⟨u, grad p⟩` holds; an outflow gives a positive-definite
  operator; a manufactured solution is recovered by all four solvers; the solvers agree with
  each other; random fields become divergence free; a div-free field is unchanged; a pure
  gradient part is removed; periodic and masked (obstacle) domains work.

## (b) The equation or algorithm each piece implements

**Discrete divergence/gradient (adjoint pair).**
`div[j,i] = (u[j,i+1]−u[j,i])/h + (v[j+1,i]−v[j,i])/h`,
`(∇p)_x[j,i] = (p[j,i]−p[j,i−1])/h`, `(∇p)_y[j,i] = (p[j,i]−p[j−1,i])/h`.

**SPD operator** `A = −∇²`:
`(Ap)[j,i] = (d[j,i] p[j,i] − Σ_touching_faces c_face p_neighbour) / h²`, where the diagonal
counts each *coupled* face once and `c_face = 0` at a wall (mirrored ghost) and at a Dirichlet
face (whose outside pressure is 0, so the diagonal gains 1 instead).

**Jacobi:** `p ← p + ω D⁻¹(b − Ap)`.
**Gauss-Seidel (red-black):** solve each colour exactly from the other colour's values.
**PCG:** `r = b − Ap`, `z = D⁻¹r`, `d = z`, iterate
`α = (rᵀz)/(dᵀAd)`, `x += αd`, `r −= αAd`, `z = D⁻¹r`, `β = (rᵀz)_new/(rᵀz)`, `d = z + βd`.
**V-cycle:** 2 Jacobi pre-smooths (`ω = 0.8`), `r_c = R(b − Ap)`, recurse, `p += P e_c`,
2 post-smooths; coarsest level solved by `lsqr` (minimum-norm, so the null space is safe).

**Projection:** solve, zero the mean (pure-Neumann case), subtract `dt ∇p` from *all* faces
including the periodic seam copies, re-apply the velocity boundary conditions.

## (c) Three to six sentences on the numerical tradeoffs

The measured cost ladder over 32²–512² is brutal and exactly as theory predicts: Jacobi does
not reach the tolerance within 4000 sweeps at any size, Gauss-Seidel needs 2569 sweeps at 32²
and never converges within budget above that, conjugate gradient needs 122 → 1712 iterations
(linear in `n`, slope 1.34 in time vs unknowns because each iteration also costs `O(n²)`),
and multigrid needs **8–9 cycles at every size** (time slope 0.34 vs unknowns). Multigrid is
the fastest solver at 128² and above but at 32² it is *slower* than CG (144 ms vs 6 ms),
because building the four-level sparse hierarchy and the `lsqr` coarse solve dominates when
there are only 1024 unknowns — a reminder that "asymptotically optimal" and "fastest" are
different claims, and both are reported. The matrix-free stencil costs one pass over two
arrays per product, so CG's 122 iterations at 32² are cheap; multigrid's per-cycle cost at
512² is dominated by resmoothing the full fine grid twice per cycle. The whole comparison is
run on the same random velocity field and the same tolerance, so the numbers are comparable;
the only asymmetry is the iteration cap, which is reported explicitly (`*` in the tables
below) rather than hidden. Getting the *sign* of the right-hand side right mattered more than
any of these choices: an initial version doubled the divergence instead of removing it, which
the tests caught immediately because they assert the *post*-projection divergence, not just
that the solver converged.

## Bugs found and fixed during this milestone (all caught by tests, all recorded)

1. **Sign of the Poisson right-hand side.** The system solves `(-∇²)p = b`; with
   `b = +div(u*)/dt` the projection *doubled* the divergence (measured: max|div| 107.8 → 215.5).
   Fixed to `b = -div(u*)/dt`.
2. **The Laplacian omitted the periodic seam.** `laplacian_apply` applied faces `1..nx-1`
   only, so a periodic problem was missing the wrap coupling and the fast diagonal term; the
   measured order of the operator's error on a periodic grid was wrong by 50×. Fixed by
   handling `cx[:, 0]`/`cy[0, :]` explicitly (and by giving them a correct diagonal).
3. **The gradient was zeroed on boundary faces.** `grid.gradient` filled the first and last
   column/row with zeros; on a periodic domain the seam face then received no correction and
   the projected field was divergence-free except in the last column (measured div 57 at the
   seam). Fixed: the seam face now carries the wrap difference and is stored twice.
4. **The projection skipped the seam copies of `u` and `v`.** Even with the correct gradient,
   the boundary faces were not updated, so the divergence in the boundary cells stayed
   O(50). Fixed by subtracting `dt·∇p` on every face, then restoring the BCs.
5. **The first multigrid hierarchy stalled.** Coarse operators were built by *re-discretising*
   at half the spacing, which is not a Galerkin pair; the V-cycle stalled at a 2.6e-3
   relative residual floor and refining the grid made it worse. Replaced with a sparse
   Galerkin hierarchy (`A_c = R A P`) built from the same face coefficients.
6. **The V-cycle silently became a direct solve.** The termination test was
   `level == last or lv.p is None`, and the finest level legitimately has `p is None`, so
   every solve did one exact hierarchical solve and reported "1 iteration". Fixed the
   termination test; the measured convergence factor is now 0.08 per cycle, independent of
   grid size.
7. **The coarsest solve produced NaNs on pure-Neumann problems.** Direct `spsolve` on a
   singular coarse matrix returns NaN; replaced with `lsqr` (minimum-norm least squares) and
   an explicit mean removal.

## Assumptions / deviations recorded in this milestone

* **D13** Divergence diagnostics *exclude solid cells*: the velocity inside an obstacle has no
  physical divergence and reporting it would be meaningless. Tests that use obstacles assert
  divergence on cells whose four faces are fluid.
* **D14** The divergence floor achievable with a given solver tolerance is
  `≈ tol · max|div| /(dt h)`; tests use `1e-6` (i.e. `tol/2` in input units) rather than the
  `1e-8` stated in the spec, because the latter is below the attainable floor at `tol = 1e-9`.
  The measured numbers are quoted, not the ideal.
* **D15** Jacobi is reported as *not converged* above 32² within 4000 sweeps. That is the
  honest result of the sweep; it is not hidden by giving Jacobi a looser tolerance.
* **D16** Multigrid uses `lsqr` on the coarsest level rather than a direct LU, because the
  coarse operator inherits the pure-Neumann singularity.

   pressure lived at the cell centres with velocities at the centres too?
2. Conjugate gradient needs ~`3.5 n` iterations to converge here, multigrid needs ~9 cycles

   places in this code where the constant mode is removed?

   terms of the solver tolerance, the grid spacing and the time step, and say which of them
